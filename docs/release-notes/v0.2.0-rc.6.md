BatCave 0.2.0-rc.6 lowers macOS monitoring overhead and steadies the interface while values update.

- macOS reads processes from the kernel process table and libproc instead of sysinfo, which re-read every process's arguments and environment each second. Local measurements on a Mac with about 760 processes roughly halved the backend's CPU use. Processes owned by other users stay listed, and values macOS won't expose are marked unavailable instead of shown as 0%.
- Process grouping, history eviction, network totals, and snapshot delivery do less work per sample. Sampling continues at full rate while the window is hidden; the interface stops polling and fills any gap in its charts when it returns.
- Explore and Overview rank and show 5-second averages, and processes join the ranking after 3 seconds, so short-lived system processes no longer push rows around. Rows that exit while you point at the list stay in place until you release it or choose "Update order".
- The workload inspector no longer shows a loading notice on every refresh, and its layout stays fixed as values change.
- "Busy now" lists only processes with sustained CPU, memory, disk, or network activity, not processes that macOS won't let BatCave read.
- The Overview removes the duplicate CPU card, names the top process with how many processes were measured, and shows the status banner only when monitoring needs attention.
- macOS host network excludes loopback traffic and reports rates again.

This is a preview. Resource use has not been re-measured against the project's performance targets since these changes. Oldest-supported-system and full installed lifecycle verification remain open. macOS kernel CPU is unavailable, and QUIC attribution has not been separately verified. Prereleases are not offered by the stable in-app updater.
