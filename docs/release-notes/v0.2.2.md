BatCave 0.2.2 keeps resource charts visible while exploring workloads and corrects telemetry, history, and Windows installer defects. It includes the collection, grouping, and update improvements prepared in [0.2.1-rc.1](v0.2.1-rc.1.md).

- Explore shows CPU, memory, disk, and network charts above the full-width workload list. Each card opens its resource inspector and restores keyboard focus when closed. Cards wrap across rows at narrow widths and increased text size.
- Wrapped chart labels no longer make cards grow on every update. Readings remain readable, and cards return to their original size when labels shorten.
- Search, sort, focus, and manual refresh apply their accepted results while the workload ranking is held. Resetting system chart history prevents late replies from restoring cleared points; workload inspection history remains available.
- Live workload histories survive archive memory pressure. Directional I/O and network averages remain consistent through idle samples, and processes with unknown start times cannot inherit earlier ranking or busy-state history.
- Linux CPU totals exclude guest time already counted elsewhere. macOS collection failures remain visible instead of appearing as successful zero readings. Missing native Windows kernel CPU remains pending while its aggregate estimate is retained.
- The Windows collector rejects unapproved client paths before reading their files. The uninstaller preserves local runtime settings and WebView data and no longer offers the broad app-data deletion checkbox.

For unavailable Windows process-network readings, check that the desktop and collector service belong to the same installed package. An obsolete per-user desktop or a development executable cannot authenticate to the current per-machine service; update both installed binaries together with the NSIS installer.

These notes prepare the version and do not establish release qualification. Corrected Explore charts still require installed native acceptance. Public A-to-B updates, failure and recovery cases, oldest-supported hosts, the complete Windows install/Start lifecycle, and native Linux and macOS update paths remain open. Windows packages retain the existing unsigned publisher policy; updater signing and macOS notarization require the release workflow.
